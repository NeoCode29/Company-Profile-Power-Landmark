Mendiagnosis dan Menyelesaikan Masalah Pengalihan Dini dalam Integrasi Sandbox iPay88I. Pendahuluan: Memahami Kegagalan Pengalihan "Senyap"Salah satu tantangan yang sering dihadapi oleh pengembang saat mengintegrasikan payment gateway iPay88 dalam mode sandbox adalah fenomena "kegagalan senyap" atau silent failure. Gejalanya sangat spesifik: setelah mengirimkan permintaan pembayaran dari situs merchant, browser tidak menampilkan halaman pemilihan metode pembayaran iPay88. Sebaliknya, browser langsung dialihkan kembali ke ResponseURL yang telah ditentukan oleh merchant, sering kali dengan status transaksi yang gagal namun tanpa pesan kesalahan yang jelas di antarmuka pengguna. Perilaku ini menandakan adanya kesalahan fundamental dan tidak dapat dipulihkan dalam permintaan pembayaran awal yang dikirimkan.Pada dasarnya, gateway iPay88 mengidentifikasi adanya masalah kritis dalam parameter yang diterima—seperti kredensial merchant yang tidak valid, tanda tangan (signature) yang tidak cocok, atau data yang cacat—sehingga proses tidak dapat dilanjutkan ke tahap pemilihan pembayaran. Dalam skenario seperti ini, perilaku bawaan sistem iPay88 adalah menghentikan transaksi dan mengembalikan pengguna ke halaman yang telah ditentukan merchant. Kurangnya pesan kesalahan yang eksplisit di sisi klien sering kali membuat proses debugging menjadi sulit dan membingungkan.Laporan ini bertujuan untuk menyediakan panduan diagnostik yang komprehensif dan sistematis untuk mengatasi masalah pengalihan dini ini. Pendekatan yang digunakan bersifat terstruktur, dimulai dari penyebab yang paling umum dan mudah diverifikasi, lalu bergerak secara progresif ke isu-isu konfigurasi, keamanan, dan arsitektur yang lebih kompleks. Dengan mengikuti metodologi ini, pengembang dapat secara efisien mengisolasi dan menyelesaikan akar permasalahan, serta membangun integrasi yang tangguh dan siap untuk lingkungan produksi.II. Tersangka Utama: Memvalidasi Persyaratan Pengujian Sandbox iPay88Penyebab paling umum dari masalah pengalihan dini saat pengujian di lingkungan sandbox iPay88 adalah kegagalan dalam memenuhi persyaratan transaksi tes yang sangat spesifik. iPay88 memberlakukan aturan ketat untuk transaksi sandbox guna membedakannya dari transaksi riil dan mencegah penyalahgunaan. Kegagalan untuk mematuhi salah satu dari kondisi ini akan mengakibatkan penolakan permintaan secara langsung oleh gateway.Tiga Pilar Transaksi Uji Coba yang ValidAgar permintaan pembayaran sandbox diterima dan diproses ke halaman pembayaran, tiga kondisi berikut harus dipenuhi secara mutlak. Setiap jumlah lain akan dianggap tidak valid dan menyebabkan penolakan transaksi.Mata Uang yang Benar: Parameter Currency harus sesuai dengan mata uang yang disyaratkan untuk jumlah transaksi tes di wilayah geografis tersebut. Ketidakcocokan antara Amount dan Currency akan menyebabkan kegagalan.Mode "Sandbox" Diaktifkan: Integrasi harus secara eksplisit dikonfigurasi untuk menunjuk ke lingkungan sandbox. Ketidakcocokan tanda tangan adalah penyebab utama kegagalan otentikasi dan pengalihan dini.Evolusi Keamanan: Dari SHA-256 ke HMAC-SHA512Secara historis, iPay88 menggunakan algoritma hashing seperti SHA-1 atau SHA-256 untuk menghasilkan tanda tangan. Namun, sebagai bagian dari upaya berkelanjutan untuk meningkatkan keamanan, iPay88 telah mengamanatkan pembaruan ke algoritma yang lebih kuat seperti HMAC-SHA512. Mengadopsi algoritma yang lebih baru tidak hanya mematuhi persyaratan terbaru tetapi juga memastikan keamanan data pembayaran yang sensitif.Rumus Tanda Tangan: Resep yang TepatPembuatan tanda tangan yang benar memerlukan perhatian cermat pada dua detail penting: urutan penggabungan string dan format parameter Amount.String Tanda Tangan Permintaan (Request Signature String):Formula Gabungan: MerchantKey + MerchantCode + RefNo + formattedAmount + CurrencyformattedAmount adalah nilai Amount yang telah dihilangkan koma dan titik desimalnya. Java:import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;
import java.nio.charset.StandardCharsets;
import java.util.Formatter;

public class Ipay88Signature {
    public static String generateSignature(String merchantKey, String merchantCode, String refNo, String amount, String currency) throws Exception {
        String formattedAmount = amount.replaceAll("[.,]", "");
        String stringToHash = merchantKey + merchantCode + refNo + formattedAmount + currency;

        Mac sha512Hmac = Mac.getInstance("HmacSHA512");
        SecretKeySpec secretKeySpec = new SecretKeySpec(merchantKey.getBytes(StandardCharsets.UTF_8), "HmacSHA512");
        sha512Hmac.init(secretKeySpec);

        byte[] macData = sha512Hmac.doFinal(stringToHash.getBytes(StandardCharsets.UTF_8));

        return bytesToHex(macData);
    }

    private static String bytesToHex(byte[] bytes) {
        Formatter formatter = new Formatter();
        for (byte b : bytes) {
            formatter.format("%02x", b);
        }
        return formatter.toString();
    }
}
